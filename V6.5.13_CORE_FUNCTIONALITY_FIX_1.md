# ApartCare Lite V6.5.13 — Core Functionality Fix 1

## Root cause found
The deployed UI calls `/api/account/create`, but the current Vercel deployment is routing that URL to the Next.js application, where it returns 404. The FastAPI `create_apartment_account()` implementation exists and the frontend submit handler is wired correctly.

## Fix
Vercel is now configured as a two-service deployment:
- `frontend`: Next.js at `/`
- `backend`: FastAPI at `/api`

The FastAPI route decorators are intentionally backend-relative (for example `/account/create`), and the service mounts them under `/api`. Local Next.js rewrites strip `/api` before forwarding to port 8000, so local and Vercel use the same API contract.

No business calculations, tenant isolation, authentication rules, or UI alignment changes were made as part of this fix.

## Critical Vercel setting
Set the Vercel Project Framework Preset to **Services** for this deployment. Keep the Root Directory as the folder containing `vercel.json`, `app/`, `backend/`, and `package.json`.

## Verification
After deployment, verify:
1. `GET /api/health` returns JSON, not Next.js 404.
2. `GET /api/account/status` returns JSON.
3. Create Apartment Account submits and receives HTTP 201/validation response.
