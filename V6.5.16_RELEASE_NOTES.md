# ApartCare Lite V6.5.16 — Production Readiness Fix

## Fixes in this release

- **Tenant isolation hardening:** property UI state is cleared immediately when the authenticated tenant changes so Account A values cannot remain visible while Account B is loading.
- **Duplicate Account Number protection:** login no longer selects the first matching tenant when a legacy state contains duplicate Account Numbers. It resolves by the supplied User ID/password; if still ambiguous, login fails closed with a clear Platform Owner repair message.
- **Opening Balance / Settings protection:** Opening Balance and Settings remain keyed by canonical `tenant_id`; stale cross-account screen state is cleared before loading the new tenant.
- **Resident Excel import persistence:** Resident Master imports now call `_save_state()` so successfully imported residents are persisted instead of disappearing after restart.
- **Import validation details:** Resident Master and Monthly Maintenance imports now display row-level validation errors returned by the backend. Users can see exactly which row/field must be corrected.
- **Import file reset:** the native Excel file picker is explicitly reset after import success/failure so the previous file selection/path is not retained.
- **Historical Monthly Data card:** widened/resized the template cards and allowed descriptive text to wrap instead of being clipped.
- **Company branding:** added `GKMA Solutions` in the main application brand area and sidebar in a restrained secondary position.
- **Mail testing:** Administration > Mail Testing now performs a real synchronous SMTP test and reports the actual delivery error instead of saying only that a background task was queued.
- **SMTP configuration:** supports `APARTCARE_SMTP_EMAIL` as the authenticated SMTP user and `APARTCARE_SMTP_SENDER` as the From/display address. Gmail App Password remains server-side only.
- **Performance:** removed the unnecessary `/admin/auth/session` round-trip before every validated property action. Protected APIs already validate the session through the backend middleware.
- **Cross-module integrity:** no changes to the canonical payment, Dashboard KPI, maintenance, expense, report, tenant calculation, or tenant-scoped data models.
