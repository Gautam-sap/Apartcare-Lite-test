# ApartCare Lite V6.5.23 — PROD1 Candidate

## Release status

This candidate is intended to be the final V6.5.23 baseline before PROD1 deployment.

## Final fixes included

1. Report export language consistency
   - Download Excel label follows selected language.
   - Download Image label follows selected language.
   - Print Report label follows selected language.
   - Share via WhatsApp label follows selected language.
   - Yearly Collection vs Expenses export title and table headers follow selected language.
   - Individual Statement export title follows selected language.
   - Direct print report table headers follow selected language.
   - WhatsApp report message follows selected language.

2. Apartment identity/header reliability
   - Login response account master is now used immediately for the apartment header.
   - Apartment name/address/account identity are not dependent on opening Settings first.
   - Platform Owner-created tenants now receive an initial tenant-scoped Settings record using the authoritative account master.
   - Existing tenant isolation and calculations are unchanged.

3. Branding
   - `Helping you run your building beautifully.` is consistently bold + italic in application branding, report print branding and generated report exports.
   - GKMA Solutions is displayed on the main property login brand in a compact professional position.

4. Core-functionality protection
   - No changes to maintenance, payment, expense, dashboard, report calculation logic, locking, RBAC or tenant-key logic were intentionally introduced.
   - Subscription payments, SMS OTP login and individual-flat UPI payments are NOT included in this release.

## PROD1 integration policy

Future Subscription Payments, SMS OTP and UPI integrations must be implemented as isolated plug-in/integration layers. They must not modify the financial calculation engine, tenant isolation rules, authentication core, locking rules or existing module APIs unless explicitly regression-tested.

## Production persistence

When `DATABASE_URL` is configured, the backend uses PostgreSQL durable persistence and creates/uses the `apartcare_state` table. The application deliberately refuses production write operations when running under Vercel without a PostgreSQL `DATABASE_URL`.

## Validation performed in the build environment

- `python -m py_compile backend/app/main.py` — PASS.
- ZIP integrity test — PASS.
- Frontend source was structurally inspected after the changes. A complete `npm run build` must be run in the Windows development environment before PROD1 push/deployment.

## PROD1 rule

Freeze this baseline after the local production build passes. Do not introduce unrelated UI or functional changes during PROD1 user acceptance testing. Any future enhancement must be developed as a separate plug-in/phase and regression-tested against this frozen core.
