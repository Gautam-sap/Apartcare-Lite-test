# ApartCare Lite V6.5.19 — User-Level Language Preference

## Scope
User-level language preference within each tenant. Multiple users in the same tenant can independently select English, Telugu, Hindi, Tamil, or Kannada.

## Safeguards
- Preference is stored on the authenticated user (`language_preference`), not in tenant business data.
- Existing legacy users inherit the tenant default once during migration.
- New users inherit the tenant default at creation and can later override it themselves.
- Account A language cannot leak into Account B because preference is resolved from the authenticated user session.
- Tenant IDs, user IDs, roles/RBAC, navigation permissions, calculations, reports, imports, payments, expenses, maintenance, dashboard KPIs and cross-module APIs are unchanged.
- Logout resets the active language to English until the next authenticated user preference is loaded.
- Missing/unsupported values safely fall back to English.

## UI
- Added **My Language** selector to the authenticated user's sidebar session card.
- Changing it persists immediately through `/api/admin/me/language`.
- Existing Settings **Default Tenant Language** remains as the fallback for newly created/legacy users; it no longer forces every existing user to change language.
- The selected language controls the tenant user's application font/script presentation.
- Translation of every English label into the selected language is intentionally not introduced in this release; this release establishes the safe per-user locale/font architecture.
