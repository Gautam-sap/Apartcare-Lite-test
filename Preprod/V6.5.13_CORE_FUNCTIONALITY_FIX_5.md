# ApartCare Lite V6.5.13 — Core Functionality Fix 5

## Purpose
Fix 5 isolates Vercel function startup from the large ApartCare application import.

## Deployment changes only
- `backend/main.py` is now a minimal ASGI dispatcher.
- `/api/health` returns HTTP 200 without importing the business application or connecting to Postgres.
- The real FastAPI application is imported lazily for account/platform/property requests.
- If the application import fails, the API returns the actual Python exception and traceback tail as JSON instead of Vercel's generic `FUNCTION_INVOCATION_FAILED`.
- `vercel.json` follows the documented Services pattern: Next.js frontend plus FastAPI backend with `/api/:path*` routing.
- No frontend, database schema, tenant logic, calculations, authentication rules, or business modules were intentionally changed.

## Test order
1. Deploy.
2. Open `/api/health`. It must return HTTP 200 JSON.
3. Open `/api/platform/status` or create Platform Owner. If the core import fails, the response will now show the exact exception.
