# ApartCare Lite V6.5.13 — Core Functionality Fix 2

## Root cause confirmed from V6.5.13 Core Functionality Fix 1

The package contained the correct FastAPI business endpoints, but the Vercel Services configuration used the obsolete `experimentalServices` key and did not define the required public rewrites.

There was a second routing mismatch: the FastAPI application exposes routes such as `/health`, `/account/create`, and `/platform/bootstrap`, while current Vercel Services rewrites preserve the `/api/...` request path.

## Fix 2

1. `vercel.json` now uses the current `services` configuration.
2. `/api` and `/api/*` are explicitly routed to the FastAPI backend service before the frontend catch-all.
3. `backend/main.py` is a Vercel service entrypoint (`main:app`).
4. The service entrypoint strips the public `/api` prefix before passing the request to the existing FastAPI application.
5. Existing business logic, tenant isolation, authentication, calculations, and UI are not changed.
6. No CSS/alignment changes are included.

## Expected checks

After deployment:

- `GET /api/health` -> HTTP 200 JSON
- `GET /api/account/status` -> HTTP 200 JSON
- `GET /api/platform/status` -> HTTP 200 JSON
- Platform Owner creation -> HTTP 200
- Apartment Account creation -> HTTP 201
- Admin login -> HTTP 200 after account creation

## Vercel

Project Framework Preset: `Services`.

Do not change the frontend to another framework preset.

Keep the existing Postgres environment variables. `DATABASE_URL` must be configured for production state-changing operations.
