# ApartCare Lite V6.5.13 — CORE FUNCTIONALITY FIX 10

## Purpose
Performance and core-flow stabilization for the Vercel + Neon/Postgres deployment.

## Changes
1. Reuse Postgres connections on warm Vercel service instances with `psycopg-pool`.
2. Stop running `CREATE TABLE IF NOT EXISTS` on every request; the state table is initialized once per warm instance.
3. Reduce state persistence to one database write per mutating request. Endpoints that already call `_save_state()` no longer trigger a second save in the mutation middleware.
4. Run the initial `/api/account/status` and `/api/platform/status` probes in parallel.
5. After Platform Owner sign-in, load Accounts, Audit History, and Subscription/Billing data in parallel.
6. Platform Owner welcome email is optional/background; SMTP configuration cannot delay Platform Owner creation.
7. Preserve the existing trial policy and default Starter/Standard/Professional plan seeding logic.
8. No UI alignment changes and no business-module redesign in this fix.

## Core acceptance tests
- `/api/health` returns HTTP 200.
- `/api/account/status` returns valid initialization JSON.
- `/api/platform/status` returns valid initialization JSON.
- Platform Owner bootstrap completes without waiting for SMTP.
- Platform Owner login completes and console data loads in parallel.
- Platform Owner password change persists successfully.
- New Apartment Account creation persists to Postgres and receives a Trial subscription.
- Refresh does not require a fresh schema/table creation operation.
