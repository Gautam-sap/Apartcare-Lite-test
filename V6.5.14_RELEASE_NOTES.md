# ApartCare Lite V6.5.14 — Production Stabilization

## P0 — Tenant Isolation
- `tenant_id` is authoritative for property data access.
- Property GET endpoints require an authenticated ApartCare session.
- Browser-supplied `tenant_id` / `apartment_id` values cannot switch an authenticated session into another account.
- Resident, payment, expense, watchman, maintenance and apartment-photo writes are forced into the authenticated tenant namespace.
- Account A state is cleared/reinitialized when a different authenticated tenant is loaded.

## P1 — Professional UX / Reports
- Per Unit Price rounds upward to the next whole value (57.39 -> 58).
- Apartment photo is resized/compressed and displayed at a controlled size, with Update and Remove actions.
- All Flats Monthly Report print view contains Water Summary + Water Detail table only.
- Print header contains apartment branding on the left and ApartCare Lite / tagline / GKMA Solutions on the right.
- Export branding is included for Image, Excel and WhatsApp.
- Global checkbox sizing remains standardized.

## P1 — Authentication / Email
- First-login users are forced to change the temporary password.
- Password reset flow is tenant-scoped.
- Welcome/new-user/reset email framework uses SMTP environment variables.
- SMTP secrets are not committed to source control.

## P2 — Performance / Production Direction
- Avoid unnecessary tenant-wide reloads and preserve tenant-scoped client state.
- Keep Vercel as the frontend/test deployment while production architecture moves toward a persistent FastAPI service + Supabase PostgreSQL/Storage.

## Email configuration
Set these deployment variables:
- `APARTCARE_SMTP_SENDER`
- `APARTCARE_SMTP_HOST`
- `APARTCARE_SMTP_PORT`
- `APARTCARE_SMTP_APP_PASSWORD`

Never commit the SMTP app password.
